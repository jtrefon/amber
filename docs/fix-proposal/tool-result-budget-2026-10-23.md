# Proposal: one budget at the context boundary, with paged artifacts (#344)

Status: P1+P4 IMPLEMENTED (2026-10-23, branch
`fix/tool-result-budget`); P2+P3 pending. Issue: #344. Taken over from the
cancelled session that filed it.

## 1. Context (measured in the issue)

Successful tool output is uncapped at the context boundary. `format_tool_envelope`
(`lib/agent_helpers.cpp:72`) caps error text at 2000 chars and inserts
`result.output` verbatim. The per-tool caps are uneven:

- `read`: up to 2000 lines x 4096 bytes/line (`tools/read_tool.cpp:40,85`) — ~8 MB worst case.
- `process_read all`: the job's 1 MiB ring — ~250k tokens.
- `bash`: 64 KiB (`tools/bash_tool.cpp:30`) — reasonable.
- compression later replaces any big tool message with `[tool output omitted]`
  (`lib/compressor_apply.cpp:354`), losing the detail with no way back.

A single long read can dominate the context and be re-sent every turn.

## 2. Target state

One enforcement point, at the tool-result to sealed-message boundary
(`lib/dispatch.cpp:463`), not per tool:

1. **Budget.** `max_tool_result_bytes` in `Config` (default 32 KiB, env
   `AMBER_MAX_TOOL_RESULT_BYTES`). Applied to the payload after envelope
   formatting, so the sealed `Message` content never exceeds budget + bounded
   header overhead (~300 B + 200 B marker).
2. **Middle-out truncation**, UTF-8 code-point safe, with a deterministic marker
   that states original bytes and the artifact id:
   `[... truncated 74 KiB of 106 KiB; full output: read_result result_id=...]`.
   `meta` gains `result_id`, `bytes`, `truncated` (and `sha256` when cheap).
3. **Artifact store** (core, host-injected; no globals): per-session directory
   under the state root, one file per oversized result, opaque ids
   (`[a-z0-9]{16}`, validated on read). Retention: 64 artifacts / 32 MiB per
   session, FIFO eviction; an evicted id returns a clear `expired` error naming
   the limit. Existing artefacts survive the session in the state dir until evicted.
4. **`read_result` tool** (read-only, no approval): `result_id`, `offset`,
   `limit`, optional `grep`. Reads only store-resolved files (id cannot address a
   path), so workspace confinement is preserved and the session log stays out of
   reach. Byte-budgeted like any other tool result; paging uses the same budget.
5. **Per-tool alignment.** `read` grows a byte cap (64 KiB) with the line limit
   as a secondary guard and returns a handle when truncated. `process_read all`
   returns the tail within budget plus a handle (delta mode unchanged). `bash`
   keeps 64 KiB and routes through the same budget so its marker carries a handle.
6. **Compression digest.** `prune_tool_io` replaces `[tool output omitted]` with
   `[tool=read status=ok bytes=81234 result_id=... first=... last=...]` so the
   model keeps an index and can page the rest.
7. **Metrics** on the debug log (per tool: result bytes p50/p95/max, truncation
   count) as the evidence for the benchmark.

## 3. Design decisions

- **Enforce once, in the boundary.** Tools keep their semantics (LSP: a `Tool`
  replacement needs no new contract); new tools inherit the cap (OCP). The store
  is a narrow port (`ArtifactStore`) with a filesystem implementation, injected
  into the agent at construction — the core stays UI-free.
- **The handle is metadata, not a second message.** The model sees the marker in
  the same tool message; no extra message, no extra LLM round-trip.
- **Truncation never splits a code point** and never drops the tail silently:
  middle-out keeps both ends, which preserves headers and final errors.
- **Eviction is explicit in the error**, never a silent miss.
- **No context rewrite**: this does not summarise or edit sealed messages; it
  only bounds what is sealed in the first place (context stays a pure stack).
- Ids are opaque and generated by the store; `read_result` resolves them through
  an index, so a hostile id cannot traverse out of the artifact directory.

## 4. Phases (each RED first, separate PRs)

- **P1 — budget at the boundary.** DONE: `max_tool_result_bytes` (`Config`,
  default 32 KiB, env `AMBER_MAX_TOOL_RESULT_BYTES`, 0 = no cap), enforcement in
  dispatch (`RecordDeps`), middle-out UTF-8 marker, `meta.bytes/truncated`,
  tests.
- **P2 — artifacts + `read_result`.** Store, retention, tool registration,
  paging/grep, confinement and eviction tests.
- **P3 — per-tool alignment.** `read` byte cap + handle, `process_read all` tail
  + handle, `bash` routed through the budget.
- **P4 — compression digest.** DONE: `tool_result_digest()` (tool, status,
  original bytes, `result_id` when present, first/last line excerpts) replaces the
  opaque placeholder; the orphaned-call stub keeps `kToolOutputOmitted`.
- **P5 — metrics + benchmark** (long-read scenario, tokens per turn and total,
  recorded in `BENCHMARK.md`), docs (`docs/spec/tools/…`, config docs), gates.

## 6. Risks

| Risk | Mitigation |
|---|---|
| Truncation hurts task success | middle-out keeps both ends; digest + handle lets the model fetch any page; benchmark gates the change |
| Artifact reads escape the workspace | ids resolve through the store only; ids validated; no path input |
| Disk growth | per-session 64 files / 32 MiB FIFO, explicit eviction error |
| A second place caps output | the boundary is the only place; per-tool caps shrink to guards |
| Existing sessions have no artifacts for old ids | marker only appears when a store exists; no back-reference for pre-store messages |

## 7. Non-goals

From the issue: LLM summarisation of already-sealed tool results (forces a
prefill), and sub-agent research/filtering as a context firewall (separate issue).

## 8. Acceptance

Mirrors the issue: a single tool call cannot inject more than the budget into the
sealed context; the full payload is recoverable through `read_result` for the
life of the session (or an explicit eviction error); compression keeps a readable
digest; the benchmark shows reduced tokens on a long-read scenario without loss
of task success.

2. Default budget 32 KiB, 0 opts out, env override.
